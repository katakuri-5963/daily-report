## 学んだこと・気づいたこと

- 画面設計と、デザインカンプ作成は違う。
  - **画面設計**は「この画面には何があり、何ができるのか」を定義するもの

    ```
    Dashboard
    ├── ヘッダー
    ├── 親タスクタイムライン
    ├── 期限状況
    │   ├── 期限超過
    │   ├── 今日
    │   └── 今週
    ├── タスク進捗
    ├── 月別完了タスク
    └── GitHub / X / Blog ...
    ```

    - タスク一覧を表示する
    - タスクをクリックすると詳細を表示する
    - 月の棒グラフをクリックすると完了タスクを表示する
    - ログインしていない場合はタスクを表示しない

    などの機能・画面構成を決める。

  - **デザインカンプ**は、それを最終的に「どう見せるか」を具体的なビジュアルとして作るもの

- 要件定義の段階で必要な画面を洗い出して「画面・帳票一覧」として整理し、さらに新規画面についてはレイアウトサンプルを作成することが望ましい
  **要件定義 → 画面設計（構造）→ ワイヤーフレーム → デザインカンプ → 実装**
